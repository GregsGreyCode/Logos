# M11 — Agents as versioned drop-in sandbox images

**Goal**: Prove one full hermes-agent runs end-to-end inside an OpenShell sandbox from the upstream `hermes-upstream:latest` image (7.46 GB, already built on this machine).

**Context**: M10 items 1-3 were reverted (`de82fb4`) because bundling Logos's Hermes fork into the sandbox via `pip install -e .` was wrong — it stuffed the entire gateway/CLI/cron into the security boundary and produced a 4.26 GB image. M11 replaces that with the NemoClaw pattern: the sandbox image IS the upstream agent runtime, Logos references it by tag. M10 items 4-5 (network policy presets, T pill UI, admin endpoints) stay intact — they're infrastructure-layer, not runtime-layer.

---

## What already exists

### The upstream image (`hermes-upstream:latest`)
- Built from `projects/knowledge-repos/hermes-agent/Dockerfile`
- Base: `debian:13.4`
- Installs: build-essential, nodejs, npm, python3, ffmpeg, ripgrep, playwright+chromium
- `pip install -e ".[all]"` at `/opt/hermes` — full hermes-agent with all extras
- Entrypoint: `exec hermes "$@"` (the hermes CLI)
- Size: 7.46 GB — acceptable for now (NemoClaw-style, bring the whole agent)

### The hermes-agent Python API
- Core class: `AIAgent` in `/opt/hermes/run_agent.py`
- Key method: `agent.run_conversation(user_message, conversation_history=[], stream_callback=None)` returns dict with `final_response`, `messages`, `completed`, token counts, cost
- Simpler: `agent.chat(msg)` returns just the string
- Constructor needs: `model`, `base_url`, `api_key` (or env vars)
- It's a pure Python class — no HTTP server, no stdin protocol. You import it and call methods.
- Thread-safe via internal locks
- Supports `enabled_toolsets` / `disabled_toolsets` for tool filtering
- `quiet_mode=True` suppresses progress output to stdout

### The current sandbox worker (`docker/sandbox_worker.py`)
- One-shot script: reads one task JSON from stdin, calls LLM via `https://inference.local/v1`, streams token/thinking/result JSON lines on stdout, exits
- Currently a **dumb LLM proxy** — does NOT use AIAgent. Just builds an OpenAI-compat chat/completions request and streams SSE chunks back
- Protocol (line-delimited JSON on stdout):
  ```
  {"type":"ready","worker_id":"..."}           ← first line
  {"type":"thinking","task_id":"...","content":"..."}  ← streamed
  {"type":"token","task_id":"...","content":"..."}     ← streamed
  {"type":"task_result","task_id":"...","status":"ok","final_response":"..."}  ← terminal
  ```
- Config loaded from `/tmp/hermes/instance-config.json` (uploaded by executor at spawn time)

### The executor (`gateway/executors/openshell.py`)
- `_DEFAULT_IMAGE` at line 110: reads `LOGOS_OPENSHELL_IMAGE` env, falls back to `docker/Dockerfile.hermes-sandbox` path (OpenShell builds from Dockerfile on demand)
- Spawn flow (3 steps):
  1. `openshell sandbox create --name <name> --from <image> --no-auto-providers [--policy <file>] -- true`
  2. `openshell sandbox upload <name> <config.json> /tmp/hermes/instance-config.json`
  3. Flip state record phase → "ready"
- No entrypoint override needed when using `-- true` — the sandbox stays alive after `true` exits (no `--no-keep`)

### The dispatcher (`gateway/worker_registry.py`)
- `dispatch_task()` spawns per-task:
  ```
  openshell -g <gateway> sandbox exec --no-tty --name <sandbox> -- python3 /app/sandbox_worker.py
  ```
- Pipes task JSON to stdin, closes stdin (EOF unblocks openshell's exec gate), reads stdout JSON lines
- Routes `token`/`thinking` events to `on_stream_event` callback, collects `task_result`
- 600s timeout (matches patched openshell-router ceiling)

## What needs to change (4 items)

### 1. Point `_DEFAULT_IMAGE` at `hermes-upstream:latest`

File: `gateway/executors/openshell.py` line 110

Currently defaults to building from `docker/Dockerfile.hermes-sandbox`. Change to:
```python
_DEFAULT_IMAGE = os.getenv("LOGOS_OPENSHELL_IMAGE", "hermes-upstream:latest")
```

The image is already on the local Docker daemon. OpenShell can reference pre-built local images by tag (mode #1 in the comment at lines 100-103).

### 2. Upload `sandbox_worker.py` into the container at spawn time

File: `gateway/executors/openshell.py`, spawn() method, after the config upload (line ~910)

The upstream image doesn't have `/app/sandbox_worker.py` — it has hermes at `/opt/hermes`. Add an upload step:

```python
# ── Step 2b: upload the sandbox worker script ──────
_worker_script = _REPO_ROOT / "docker" / "sandbox_worker.py"
if _worker_script.exists():
    _openshell(
        "sandbox", "upload", sandbox_name,
        str(_worker_script), "/app/sandbox_worker.py",
        gateway=openshell_gw, check=True,
    )
```

This keeps the worker decoupled from the image — Logos owns the protocol bridge, the image owns the agent runtime.

### 3. Rewrite `sandbox_worker.py` to use `AIAgent`

File: `docker/sandbox_worker.py`

Replace `_run_inference()` (the raw aiohttp LLM proxy) with an `AIAgent.run_conversation()` call. The key change:

```python
import sys
sys.path.insert(0, "/opt/hermes")  # upstream image installs hermes here
from run_agent import AIAgent

async def _handle_task(task, config):
    task_id = task.get("task_id", "")
    message = task.get("message", "")
    history = task.get("history", [])

    agent = AIAgent(
        model=config.get("model", ""),
        base_url=os.environ.get("OPENAI_BASE_URL", "https://inference.local/v1"),
        api_key=os.environ.get("OPENAI_API_KEY", "unused"),
        max_iterations=90,
        quiet_mode=True,
        enabled_toolsets=config.get("toolsets") or None,
    )

    # Convert history to the format AIAgent expects
    conversation_history = []
    for h in history:
        if h.get("content"):
            conversation_history.append({"role": h["role"], "content": h["content"]})

    result = agent.run_conversation(
        user_message=message,
        conversation_history=conversation_history if conversation_history else None,
    )

    # Stream the final response as tokens (AIAgent doesn't natively
    # stream via callback in a way that maps to our JSON-lines protocol,
    # so for the proof-of-concept we emit the full response as one token)
    emit({"type": "token", "task_id": task_id, "content": result["final_response"]})
    emit({
        "type": "task_result",
        "task_id": task_id,
        "status": "ok",
        "final_response": result["final_response"],
    })
```

**Important considerations:**
- `AIAgent` is synchronous (not async). The worker's `_handle_task` is currently async. Either wrap in `asyncio.to_thread()` or make `_handle_task` sync since the worker is one-shot anyway.
- `AIAgent.run_conversation()` has a `stream_callback` parameter — investigate if it can be used to emit per-token events for real streaming. If so, wire it to `emit({"type":"token",...})`.
- The worker currently uses `aiohttp` for the raw proxy. With AIAgent, aiohttp is no longer needed — AIAgent uses its own HTTP client internally.
- `/opt/hermes` needs to be on PYTHONPATH. Either `sys.path.insert(0, "/opt/hermes")` in the script, or set `PYTHONPATH=/opt/hermes` in the exec command.

### 4. Update the exec command to set PYTHONPATH

File: `gateway/worker_registry.py` around line 330-340

Current:
```python
cmd = [... "--", "python3", "/app/sandbox_worker.py"]
```

Add env or update to:
```python
cmd = [... "--", "bash", "-c", "PYTHONPATH=/opt/hermes exec python3 /app/sandbox_worker.py"]
```

Or if openshell exec supports `--env`:
```python
cmd = [... "--env", "PYTHONPATH=/opt/hermes", "--", "python3", "/app/sandbox_worker.py"]
```

Check `openshell sandbox exec --help` to see if `--env` is supported.

## Issues discovered and fixed during testing (2026-04-12)

| # | Issue | Root cause | Fix |
|---|-------|-----------|-----|
| 1 | Sandbox stuck in `Provisioning` forever | `:latest` tag → k8s sets `imagePullPolicy: Always` → tries to pull from a registry that doesn't exist | Use pinned version tags (e.g. `hermes-sandbox:m11`). k8s uses `IfNotPresent` for non-latest tags. |
| 2 | Pod fails: "sandbox user not found in image" | OpenShell requires a `sandbox` user (uid/gid 10001) in every sandbox image. Upstream hermes image doesn't have one. | Wrapper Dockerfile adds `groupadd/useradd` for sandbox:10001. |
| 3 | Pod fails: "Network namespace creation failed" | OpenShell's in-sandbox agent needs `iproute2` for network namespace setup. Upstream hermes image doesn't include it. | Wrapper Dockerfile installs `iproute2`. |
| 4 | `PermissionError: /opt/hermes/run_agent.py` | OpenShell's sandbox policy blocks `/opt/` at runtime. The upstream editable install (`pip install -e`) reads source from `/opt/hermes`, which is inaccessible. | Wrapper Dockerfile re-installs hermes-agent as non-editable (`pip install --break-system-packages /opt/hermes`), which copies code to `/usr/local/lib/python3.13/dist-packages/` (readable). |
| 5 | Upload fails: "Permission denied: /app/" | OpenShell restricts write paths. `/app/` is not in the writable set. Only `/tmp/` and `/sandbox/` are writable. | Upload worker to `/tmp/` instead of `/app/`. |
| 6 | `PermissionError: /home/sandbox/.hermes` | OpenShell makes home directory read-only at runtime. AIAgent's `setup_logging()` tries to create `~/.hermes/logs`. | Set `HERMES_HOME=/tmp/hermes` in the exec command so AIAgent writes logs/state to the writable `/tmp/hermes` directory. |
| 7 | Image import into OpenShell takes ~60-120s | OpenShell runs containerd inside a Docker container. `docker save \| ctr import` must pipe the full image (~7.46 GB) through Docker's stdin. | Pre-import with `docker save <image> \| docker exec -i <cluster> ctr -n k8s.io images import -`. After first import, sandbox creates are near-instant (~6s). |
