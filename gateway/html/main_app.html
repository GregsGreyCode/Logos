Sandbox Policies
OpenShell network egress rules. Applied per-agent; saving hot-reloads every live sandbox using the preset.
What are sandbox policies?

Every Logos agent runs in an isolated OpenShell sandbox that blocks outbound network traffic by default. A preset is a YAML file that grants access to specific hostnames and ports — e.g. the github preset lets agents reach api.github.com, nothing else.

When you apply a preset to an agent (from the agent's Tools tab), the sandbox merges it into the baseline policy and starts allowing those endpoints. Removing a preset revokes access.

When to add / edit a preset
  • A new third-party API your agents need to call (add a preset, apply it to the agent).
  • An existing preset is too permissive or too restrictive (edit its endpoints).
  • A service changed hostnames (update host glob).
Key fields in a preset
  • host — hostname or glob, e.g. api.github.com or *.amazonaws.com.
  • port / ports — TCP port(s). 443 for HTTPS.
  • protocol — rest for HTTP APIs, sql for databases, omit for L4 only.
  • tls — usually terminate (gateway decrypts so L7 rules can match paths).
  • enforcement — enforce blocks violations, audit logs only.
  • access — shortcut: full / read-only / read-write. Or use rules: for method+path control.
Safe to edit / don't edit
  • Change endpoints, hosts, ports, L7 rules — hot-reloads without restarting sandboxes.
  • Don't rename the preset (preset.name) — the filename and applied-list won't match and agents will silently lose the policy.
  • Syntax errors are rejected at save time; your changes are never partially written.

Souls
Agent personas. Each soul is a directory with a soul.manifest.yaml (metadata + toolset policy) and a soul.md (persona content).
What are souls?

A soul is an agent's persona — its communication style, default toolset policy, and voice. Each soul lives in souls/<slug>/ with two files:

  • soul.manifest.yaml — metadata (id, slug, name, description, category, status) + toolset policy (enforced / default_enabled / optional / forbidden).
  • soul.md — markdown describing how the agent speaks, reasons, and behaves.
Editing rules
  • The manifest's slug must match the URL/filename slug — otherwise the registry goes out of sync with the filesystem.
  • Saving hot-reloads the in-process soul registry. The next agent dispatch picks up the new manifest without a gateway restart.
  • A soul can only be deleted if no agent currently uses it (migrate agents first).
  • enforced toolsets are always enabled; users can't untick them in the agent editor. forbidden toolsets are always disabled. optional toolsets are user-togglable.

Factory reset?

This will destroy:

  • Every agent, its sandbox, sessions, memories, and logs
  • Every model route and its OpenShell gateway
  • The dispatch ledger, run history, evolution proposals, and audit log
  • All users — including yours. You'll be logged out and the setup wizard will mint a fresh admin account.

Souls + skill catalogue are kept (platform fixtures, not your data). This cannot be undone.

Re-run setup wizard?

This will re-open the setup wizard. You can reconfigure the model server, agent settings, and replace the admin account credentials.

Any additional users you created during the previous setup will remain. Existing sessions and chat history are unaffected.
